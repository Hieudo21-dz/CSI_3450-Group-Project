Challenges
 
and
 
Solutions
 
Multiple
 
allergies
 
per
 
customer:
 
A
 
customer
 
can
 
have
 
several
 
allergies,
 
and
 
each
 
allergen
 
affects
 
many
 
customers.
 
Storing
 
allergies
 
in
 
columns
 
such
 
as
 
Allergy1
 
and
 
Allergy2
 
would
 
cap
 
the
 
number
 
and
 
make
 
searches
 
hard.
 
Solution:
 
Used
 
a
 
CUSTOMER_ALLERGY
 
bridge
 
table
 
with
 
a
 
composite
 
primary
 
key
 
(CustomerID,
 
AllergenID).
 
A
 
customer
 
can
 
have
 
any
 
number
 
of
 
allergies,
 
each
 
with
 
its
 
own
 
severity,
 
and
 
the
 
same
 
allergy
 
can’t
 
be
 
recorded
 
twice.
 
Enforcing
 
the
 
order
 
safety
 
rule:
 
The
 
most
 
important
 
rule
 
is
 
that
 
an
 
unsafe
 
dish
 
can
 
never
 
be
 
added
 
to
 
a
 
customer’s
 
order.
 
Checking
 
it
 
only
 
in
 
the
 
web
 
app
 
would
 
be
 
risky,
 
because
 
any
 
other
 
route
 
into
 
the
 
database
 
would
 
skip
 
the
 
check.
 
Solution:
 
Enforced
 
the
 
rule
 
inside
 
SQL
 
Server
 
with
 
a
 
trigger
 
on
 
ORDER_ITEM.
 
It
 
compares
 
the
 
dish’s
 
allergens
 
with
 
the
 
customer’s
 
allergies
 
and
 
rejects
 
the
 
item
 
with
 
a
 
clear
 
message
 
naming
 
the
 
dish,
 
the
 
allergen
 
and
 
the
 
customer.
 
 
Keeping
 
order
 
totals
 
correct:
 
TotalAmount
 
is
 
calculated
 
from
 
the
 
items
 
on
 
an
 
order.
 
If
 
the
 
app
 
had
 
to
 
update
 
it
 
by
 
hand,
 
it
 
could
 
easily
 
get
 
out
 
of
 
sync.
 
Solution:
 
A
 
second
 
trigger
 
recalculates
 
the
 
total
 
whenever
 
items
 
are
 
added.
 
Running

SQL
 
Server
